# Browser Concurrency Lock

Статус: **as-built**.

## Goal

Не дать worker и UI (или двум операциям) одновременно управлять одним профилем
Edge — это причина зависаний «profile locked», которые ловили многократно.

## Scope

- `browser_lock.py`: `acquire(owner)`, `release()`, `is_busy()`, `status()`, контекст-менеджер `browser_lock`.
- Файл `data/browser.lock` (owner+pid+ts), TTL — устаревший лок игнорируется.
- Интеграция: worker берёт лок на браузерную фазу тика; UI-операции с браузером отказываются, если занято.

## User-visible behavior

- Если worker сейчас в браузере — UI-кнопки скрейпа/сабмита/импорта/sync покажут «браузер занят, повторите позже».
- И наоборот: worker пропускает браузерную фазу тика, если UI держит лок.

## Invariants

- Тот же pid может перевзять лок (реентерабельно в рамках процесса).
- Лок старше `TTL_SECONDS` (по умолчанию 600) считается мёртвым → свободен.
- `release()` снимает лок только своего pid (или мёртвый).

## Edge cases and failure policy

- Повреждённый/нечитаемый lock-файл → считается свободным.
- Крах держателя → лок протухает по TTL, система не блокируется навсегда.

## Verification mapping

- `tests/test_browser_lock.py`: цикл acquire/release, реентер своего pid, блок чужого pid, протухание, контекст-менеджер.

## Unknowns

- Нужно ли увеличивать TTL для очень долгих браузерных операций (импорт многих диалогов).

# AGENTS.md

Правила работы агента в этом репозитории. Источник: [spec-first-bootstrap](https://github.com/ostrowsky/spec-first-bootstrap).

**Детальное поведение продукта — в `docs/specs/`, не здесь.**

## Порядок чтения

Перед реализацией:

1. `AGENTS.md` (этот файл)
2. `docs/specs/README.md`
3. `docs/specs/product-map.md` — карта продукта
4. Релевантная спека в `docs/specs/features/`
5. Только после этого — код

## Spec-First Rule

Перед любой нетривиальной фичей:

1. Уточнить продуктовую цель.
2. Создать или обновить спеку в `docs/specs/features/`.
3. Зафиксировать поведение, инварианты, граничные случаи.
4. Реализовать по контракту спеки.

## Когда спека обязательна

- новая фича
- изменение наблюдаемого поведения UI / API / worker
- новые или изменённые сущности БД, статусы, контракты
- многошаговые сценарии (отклик, переписка, отчёт)
- логика skip/apply, лимиты connects, gating

Спека **не обязательна** для: чистый рефакторинг, форматирование, комментарии без смены поведения.

## Три слоя (не смешивать)

| Слой | Назначение |
|------|------------|
| `docs/specs/` | Продуктовая правда — что система делает |
| Код (`app.py`, `worker.py`, …) | Реализация контракта |
| `qa/` / тесты | Доказательство, что контракт выполняется |

## Правила этого проекта

- **LLM:** OpenRouter через `ai.py`; модель из `OPENROUTER_MODEL`.
- **Upwork:** браузерная сессия Playwright, профиль `data/upwork_profile`; см. `docs/specs/features/upwork-browser-session.md`.
- **UI:** Streamlit (`app.py`); не запускать долгий цикл автоматизации внутри Streamlit — worker отдельно.
- **Секреты:** только `.env`, не коммитить `data/upwork_profile/`, `data/upwork_storage_state.json`.
- Поведение изменилось → спека обновляется **в том же PR/задаче**, что и код.

## Верификация

При изменении поведения — обновить или добавить проверку: pytest, `python upwork_connect.py`, ручной чеклист в спеке (секция Verification mapping).
